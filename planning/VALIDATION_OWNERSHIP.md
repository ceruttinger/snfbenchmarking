# Validation and organizational ownership expansion

Workforce endpoint screening preserves 63 flagged 2019/2024 comparisons in a review queue. The national summary uses 4,052 remaining matched general short-term hospitals; 1,941 increased annualized patient days per payroll FTE. Separate medians: payroll FTE growth 4.41%, annualized patient-day growth 2.70%. More-than-fourfold changes in payroll FTEs, annualized patient days or patient days per FTE trigger review. These thresholds are exploratory review criteria, not proof of reporting errors or shortages. Payroll/workload change rankings use the same review screen and disclose exclusions; guided raw target trends retain reported values and warn on flagged target endpoints. Resident-FTE and salary-only rankings are not subject to this payroll endpoint screen.

A bounded, non-random API audit re-queried 30 endpoint records: the ten largest flagged workforce cases and five flagged capacity cases, both endpoints. All selected fields matched the fresh CMS responses. This validates extraction inputs, not the accuracy of provider filings or their staffing scope. A striking example is CCN 210044: the 2024 CMS report itself reports 54.97 payroll FTEs and $332,742,911 Worksheet A salaries. No correction or shortage conclusion is inferred. All 63 workforce flags and 16 capacity flags remain open for substantive review.

The organization-only network covers retained CCN units for Hospital, SNF, Home health, Hospice, FQHC and RHC. Renal and CMHC add institutional enrollment identities only; their ownership is not supplied by this layer. No individual owner names or addresses are retained. Non-hospital roster rows without a numeric six-character CCN or legal organization name are omitted and counted in coverage; this is not a complete site census. Categories mix CCN units and Medicare enrollment identities and must not be summed as physical sites. Financial benchmarking still covers hospitals only.

Cross-category linkage uses exact CMS organizational associate IDs, not name similarity. A shared direct/indirect ownership-interest organization is not a resolved ultimate-parent system. Partnership interests are ownership associations; operational/managerial control is distinct. Security and mortgage interests, ADP, trustee and other roles stay neutral reported associations. Earlier hospital convenience edges that promoted such roles to control are reclassified; the original assertion nodes, role text and source evidence are retained.

There are 149,155 organizational role assertions in the derived network and 2,355 exact organizational IDs with reported ownership interests in at least two categories. Source dates differ: hospital disclosures August 2026, other owner categories October 2026, renal/CMHC enrollment July 2026. This is a cross-snapshot descriptive footprint, not simultaneous ownership or a dated operating hierarchy.

The hospital CHOW API contributes 779 source-reported events with effective dates, buyer/seller organizational identities and CCNs. Events are not a complete continuous ownership history. Neither a date match nor a before/after workforce change establishes an acquisition effect. Historical-owner chatbot questions still clarify this limitation and direct users to the event inspector.

Rebuild source metadata with the official CMS data.json catalog (metadata only), selecting API accessURL entries and preserving source vintages. `ai/network-sources.json` freezes the selected catalog metadata. `ai/build_network.py` fetches projected JSON API columns in memory and persists only derived organizational evidence in private, ignored network.json. `ai/network.py` writes public aggregate coverage and bounded footprint summaries; `/api/network` returns up to 100 related facilities and 50 target events. The public site never receives the complete organizational snapshot. Lambda packages it privately; static deployment explicitly excludes it.

Run engine, workforce, validation/network and graph tests. Build semantic catalog 1.1.1, policy summaries, graph artifact and Lambda package before deployment. The graph adds Facility and OwnershipEvent nodes, exact-ID organization links, source snapshots and role-specific assertions to the existing instance. It does not replace the database. Existing cost-report observations and previous catalog/source lineage are retained. The graph update temporarily starts a stopped instance and restores its previous stopped state after verification; credentials stay server-side.
